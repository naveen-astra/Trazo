# TrazoBench

An open benchmark for agent-observability tooling (RESEARCH.md RQ3):
failure-injected multi-agent traces across two frameworks, ground truth
labels, metric definitions, and a runner that scores **any** tool exposing
a small adapter interface — not just Trazo's own.

## TrazoBench v0 — 2026-07-30

- **Detection corpus** (`corpus/failure_index.json`): 300 runs across two
  frameworks/demo projects (`research-assistant`/LangGraph,
  `content-pipeline`/CrewAI), 150 each — 50 clean + 25 apiece of the four
  taxonomy classes (loop, budget, thrash, drift; AI_DEBUGGER.md §1).
  Regenerate with `benchmark/corpus/generate_failure_corpus.py`.
- **Detection adapters** (`adapter.py`): `DetectionAdapter` Protocol
  (`detect(events) -> list[Detection]`); `TrazoDetectorAdapter` (reference,
  wraps Trazo's own Loop/Budget/Thrash detectors) and
  `RandomFlaggerAdapter` (the trivial baseline).
- **Replay adapters** (`adapter.py`): `ReplayAdapter` Protocol
  (`replay(run_id, endpoint=...) -> dict`, shaped like `trazo verify
  --json`'s own stable output); `SubprocessReplayAdapter` (reference,
  wraps each demo's `replay_entrypoint.py`).
- **Fidelity corpus** (RQ1): needs the nightly corpus job's real LLM calls
  (`TRZ-P3-05`) to accumulate runs — not available in the environment this
  was built in. The fidelity harness itself is verified against two
  genuine recorded runs (RESEARCH.md RQ1's own note): 100% boundary
  fidelity, 100% state fidelity, zero divergences.

## Scoring your own tool

**Detection (RQ2).** Implement `DetectionAdapter`:

```python
class MyDetector:
    def detect(self, events: list[Event]) -> list[Detection]:
        ...  # your own logic; return every Detection found
```

Score it against the labeled corpus (`runner.py` needs `benchmark/` on
`sys.path` — see its own module docstring):

```python
from pathlib import Path
from runner import load_entries, score_corpus

entries = load_entries(Path("benchmark/corpus/failure_index.json"))
results, skipped = score_corpus(
    entries, Path("benchmark/corpus/_runs/.trazo/cache"), MyDetector()
)
```

Or run `benchmark/detection/runner.py` directly for Trazo's own numbers
plus the random-flagger baseline (see below).

**Replay (RQ1).** Implement `ReplayAdapter` and register it in
`benchmark/fidelity/run_harness.py`'s `_DEMO_ADAPTERS` under your own
project name.

## RQ2 baseline comparison (flag-any-fault)

Generated by `uv run --project sdk python benchmark/detection/runner.py`
against the 300-run corpus above. Per-class precision/recall/FPR/latency
numbers live in `detection/results.md` (regenerated, not committed —
reproducible from the corpus, not prose). The random-flagger baseline has
no notion of loop/budget/thrash classes, so it's compared at the binary
"did this tool flag anything in this run" level instead, which is what
RESEARCH.md RQ3 means by "anchor the scale":

| Adapter | Corpus (faulty) | Precision | Recall | FPR (clean) |
|---|---|---|---|---|
| Trazo (loop+budget+thrash) | 200 | 100% | 75% | 0% |
| Random flagger (5% per-event) | 200 | 71% | 82% | 67% |

The random baseline's recall isn't dramatically lower than Trazo's — with
enough boundary events in a run, even a low per-event flag rate has good
odds of hitting *something*. Its failure mode shows up in precision and
FPR instead: two-thirds of clean runs get a spurious flag. That's the
actual anchor — a tool that isn't really detecting anything can still
look decent on raw recall, which is exactly why RQ2/RQ3 report precision,
recall, *and* FPR together rather than any one number alone.
